# v0ca. — Stats and achievements

What the app counts, where it keeps it, and what is planned. The shelf on the
Stats tab is the visible half; `stats.json` and `achievements.json` next to the
history are the other one.

## How it is stored today

**`stats.json` — one row per day**, keyed `yyyy-MM-dd` in local time. Independent
of the recording history: history gets trimmed by its limits, stats accumulate
forever. Fields: `words`, `chars`, `dictations`, `seconds`, `hours` (dictations
by hour of day, string keys), `maxWords`, `maxWordsPerMinute`, `asks`, `screens`,
`maxAskWords`.

Every field added after the first release decodes with a default, never a throw:
a missing key must not cost a user their whole history of numbers. Old days are
not backfilled — a counter starts from zero on the day it ships, and the UI
should say so rather than imply the totals are complete.

**`achievements.json` — flags only.** Everything countable is recomputed from
stats on every read, so a long-time user never opens the tab to an empty shelf.
Persisted are the things that leave no trace in the numbers: a screenshot sent in
silence, a question cancelled during the countdown, an answer regenerated, which
engine has run, which provider has answered.

## Planned: the catalog moves to JSON

The catalog is Swift today — eleven groups built by hand, ladders generated by
loops. That is fine for eleven and wrong for thirty, and `modules/OVERVIEW.md`
already says this class of thing belongs in data.

`Resources/AchievementCatalog.json`, loaded like `ModelCatalog.json`:

```json
{
  "groups": [{ "id": "traffic", "title": "<group name>" }],
  "achievements": [
    { "id": "traffic.first", "group": "traffic", "title": "<title>",
      "icon": "arrow.down.circle", "metric": "optimizedShots", "goal": 1,
      "caption": "<what to do while locked>" },
    { "id": "traffic.100mb", "group": "traffic", "title": "<title>",
      "icon": "internaldrive", "metric": "savedBytes", "goal": 104857600,
      "format": "bytes", "caption": "<caption with %@ for the goal>" }
  ]
}
```

Titles and captions in the real file are the Russian source strings, because
those double as the keys for `L()`; they are elided here to keep this document
in one language.

Rules that keep this from becoming a rules engine:

- **`metric` names a registry entry in code** — a table of name → closure pulling
  a number out of `StatsStore`. An unknown metric is skipped, not an error: the
  same rule that already protects the flags file. The logic stays in Swift; only
  the choice moves to data.
- **All-or-nothing achievements carry `flag` instead of `metric`.** The flag list
  stays an enum: code is what marks them, so code has to know them.
- **`format` picks how progress renders** — plain number, hours, bytes. The
  formatting is code; the file only names which one.
- **Ladders are written out row by row.** Loops are shorter; explicit rows are
  honest — what is in the file is what the user sees.
- Titles and captions stay in the base language: they are the keys for `L()`,
  and the translations go on living in `L10n.en`. The localization audit script has to
  learn to read this file too (`modules/PLAN.md`, step 8).

Order of work: move the existing catalog to JSON with **no new achievements**,
confirm the shelf looks exactly as before, and only then add rows.

## Planned: new counters

### Screenshot optimization: one achievement, no counter

**Decided: we do not measure the saved traffic.** With the module on, the
baseline image is never produced, so there is nothing to subtract from. Getting
a real number means encoding every screenshot twice — tens of milliseconds spent
so a counter can go up. Estimating the baseline from the pixel count would be
free and dishonest: JPEG size depends on what is on screen. A ladder of
megabytes is not worth either price.

So: no `savedBytes`, no `optimizedShots`, no new fields in `stats.json`. One
all-or-nothing achievement on a flag, marked the first time a screenshot is
squeezed:

| Flag | Condition |
|---|---|
| `optimizedShot` | a screenshot was sent through the optimizer |

It belongs to the existing screenshots group rather than a new one — one
achievement is not a group. It is only reachable while the module is on, which
is the point: the shelf shows that the module did something, and says nothing it
cannot back up.

### Recording length

`DayStats` gains `durations: [String: Int]` — counts per bucket, keys `"0-5"`,
`"5-15"`, `"15-30"`, `"30-60"`, `"60-120"`, `"120-180"`, `"180-300"`,
`"300-600"`, `"600+"` in seconds, the nine buckets the stats mockup draws — and
`maxSeconds`, the longest single dictation of the day, which nothing tracked
before. String keys for the same reason `hours` uses them: integer keys would
encode as a flat array.

On the tab it becomes a second card beside the hour map, drawn the same way:
nine columns on the same heat ladder, the share printed inside each, and a footer
with three coarse groups and the longest recording.

Achievements, a new "length" group (10 rungs, three axes — long recordings,
short ones, and coverage):

| # | Goal | Metric |
|---|---|---|
| 1 | a recording ≥ 1 min | `maxSeconds` |
| 2 | ≥ 3 min | `maxSeconds` |
| 3 | ≥ 5 min | `maxSeconds` |
| 4 | ≥ 10 min | `maxSeconds` |
| 5 | ≥ 30 min | `maxSeconds` |
| 6 | 100 recordings under 15 s | `shortDictations` |
| 7 | 500 recordings under 15 s | `shortDictations` |
| 8 | at least one recording in every bucket | `filledBuckets` |
| 9 | 60 min of speech in one day | `bestSecondsInDay` |
| 10 | 180 min of speech in one day | `bestSecondsInDay` |

`shortDictations` is the `"0-5"` and `"5-15"` buckets summed over all days;
`filledBuckets` counts how many of the nine buckets are non-empty, goal 9.

### Words in a day

Already shipped as `records.words.day` (goal 1000) against
`bestWordsInDay`. Nothing new to store — the ladder grows to 10 rungs:

1 000 · 2 000 · 3 000 · 5 000 · 7 500 · 10 000 · 12 500 · 15 000 · 20 000 · 25 000

For scale: 1 000 words is roughly seven minutes of steady speech, 10 000 is
around an hour and a half, and the last two rungs are a deliberate ceiling — a
place to aim rather than a weekly errand.
